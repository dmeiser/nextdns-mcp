# ADR 0001 — OpenAPI-spec-generated tools ("parser, not transport")

Status: accepted (4.0.0). Applies to `src/nextdns_mcp/spec_tools.py`,
`src/nextdns_mcp/nextdns-openapi.yaml`, and everything that verifies them.

## Context

The server used to publish a hand-written surface of eight tools grouped by resource
area: profiles, settings, lists, rewrites, logs, analytics. Each tool chose what to do
with an argument that named the action, and each one restated in Python what the NextDNS
API already documents: the endpoint, the parameters, the shapes, the descriptions. That
restatement was the cost. Adding an endpoint meant writing a tool and its tests; a
parameter the grouped tool forgot was invisible to the caller; descriptions drifted from
the API; and the surface could only grow as a set of grouped verbs, so an account with
dozens of distinct endpoints was reachable through a handful of overloaded entry points.

Two options were on the table:

1. **Keep the grouped surface** and keep hand-maintaining the mapping from tool to
   endpoint. Cheap to reason about, permanently expensive to keep correct, and it makes
   the catalog's completeness a matter of memory.
2. **Generate one tool per operation** from a bundled OpenAPI document of the NextDNS API
   — the document the repo already maintains and lints, and which already drives schema
   validation and the E2E coverage assertion.

There was also a shortcut available for option 2: FastMCP's `FastMCP.from_openapi()`
builds a server from a document in one call. It was tried and rejected (issues #141 and
#146): the tools it generates issue their own HTTP requests through FastMCP's OpenAPI
transport. That transport does not go through this project's `AccessControlledClient`, so
the per-profile read/write allowlists, read-only mode, the protected-profile denylist, URL
redaction, and the typed error payload contract would all have been bypassed on every
generated call. It also raises on a non-2xx status and discards the upstream body, which
is the one piece of information a caller needs when a call fails.

## Decision

**Publish one tool per `operationId` of the shipped OpenAPI document, generated by
FastMCP's OpenAPI parser, with the transport kept ours.** In the shorthand the code uses:
*parser, not transport*.

- `src/nextdns_mcp/spec_tools.py` hands the document to `parse_openapi_to_http_routes`
  and wraps each route as a `SpecApiTool`: the tool's name is the `operationId`, its
  description is the document's own summary/description, and its `inputSchema` is that
  endpoint's path, query, and request-body fields flattened one level.
- `SpecApiTool.run()` executes through `transport._api_request_payload`, i.e. the
  access-controlled client, and returns the server's typed error payloads. `Tool.run` is
  the only FastMCP behaviour the class relies on.
- Arguments are validated against the endpoint's published schema before a request goes
  out, so a schema-invalid call is refused locally instead of round-tripping an error.
- Nothing about a tool is restated in Python: names, descriptions, enums, defaults and
  examples live in the YAML, and the only place to tune what a caller sees is the YAML.

The document is the contract, which means the checks that matter are catalog-to-document
checks: `scripts/validate_schema.py`'s `assert_operation_coverage()` compares the served
catalog against the document in both directions, `scripts/run_container_e2e.py` calls it
at startup and hard-fails on drift, and the container test pins the served catalog to
`published_tool_names()`.

## Deviations from a pure proxy

The generator is a proxy for the document, with the exceptions below recorded here because
a silent exception is what makes a generated surface impossible to trust. They are also
recorded where they are implemented (`spec_tools.py`).

1. **Query normalizers for the analytics window** (`_QUERY_NORMALIZERS`: `from`, `to`,
   `partials`). Two spellings callers reach for fail *silently* upstream rather than
   erroring: a bare negative `from` reads as an absolute 1969 timestamp and answers 200
   with no rows, and the `now-1d` spelling is rejected. `partials=false` answers a 400
   that names no allowed value. The rewrite is exact and total — `-86400` → `-86400s`,
   `false` → `none` — and it exists because a caller with nothing to act on retries.
   `partials` accepts `none` and `all`; the window arguments accept epoch seconds (as a
   number) and the string spellings the API honours, including relative offsets and
   `now`.
2. **Operations the transport cannot carry.** `streamLogs` is withheld: it is a
   Server-Sent Events stream, and a tool call is request/response, so publishing it would
   publish a tool that cannot answer. `downloadLogs` is delegated: the endpoint answers
   with a redirect to a signed URL, and the safe way to follow it — size cap, per-hop
   public-address checks, no API key on the follow-up request — already lives in
   `tools/logs.py`, so the generated tool hands off to that instead of duplicating it.

A guardrail is not a deviation: `_UNSAFE_PATH_VALUE` refuses a path argument that could
address a *different* endpoint (`/`, `?`, `#`, `\`, whitespace, `..`, non-printables),
which only ever fires on a value that would not have meant this tool's operation anyway.

## The composite visual and lookup tools are declared exceptions

`overviewDashboard` and specialized analytics widgets, `plotAnalytics` (compose several series into an interactive Prefab chart), and `dohLookup` (resolve a name over
the DoH endpoint) do things no endpoint describes, so the published catalog is **not**
fully derivable from the document: `published_tool_names()` combines the generated names
with the composite tools, and they are registered beside them. This is the accepted cost of
the decision, stated rather than discovered later — the document generates 78 of the
published tools and names none of the composites. Adding a new composite means touching
the registration list and the validation script's catalog policy, which is the point at
which a `x-mcp-composite`-style declaration in the YAML would start paying for itself.

## Consequences

**Gained**

- The catalog is complete by construction: an endpoint added to the document becomes a
  tool, with the description and schema that come with it.
- One place owns what a call accepts, so the tool listing, the validation tooling, and
  the E2E expectations cannot disagree with each other about a parameter.
- The ACL, the destination allow-list, redaction, and the typed error contract stay on
  every call path, generated included.
- Drift has a mechanical check: `assert_operation_coverage()` fails when the catalog and
  the document part ways in either direction.

**Accepted costs**

- An edit to the document changes the published surface — including the names a caller
  sees — so document changes are breaking-change surface and get treated as such.
- Profile-id shape is part of the published schema, and both accepted lengths (6 or 10
  lowercase alphanumeric characters) have to be stated there; a schema that names one
  length rejects the other at the client.
- The two deviations above mean a spec change to `from`/`to`/`partials` or to the
  download redirect has to be made in two places.
- `streamLogs` cannot be exposed as a tool at all; a caller wanting live query events
  needs `getLogs`/`downloadLogs` polling instead.

**On top of the surface**

Progressive disclosure is a separate layer over this catalog, not part of the generation
decision. `NEXTDNS_TOOL_SEARCH` (default `bm25`) replaces `tools/list` with FastMCP's
synthetic `search_tools` + `call_tool` pair so an 80-tool listing does not have to fit in
a context window; the generated tools stay callable, and access control is unchanged —
disclosure hides names, it does not grant or withhold permission. `NEXTDNS_TOOL_SEARCH=off`
publishes the full listing. The decision is independent of this ADR: turning disclosure off
leaves exactly the surface described above.

## History

- Issues #141 and #146: `FastMCP.from_openapi()` rejected — its transport bypasses
  `AccessControlledClient` and drops the upstream error body.
- 3.x: the grouped, hand-written surface, with OpenAPI generation attempted and removed
  once for the same transport reason.
- 4.0.0: the grouped surface is removed; generation returns with the transport owned here.
